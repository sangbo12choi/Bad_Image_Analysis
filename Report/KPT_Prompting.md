# KPT 회고 프롬프트 가이드

## 개요

이 문서는 KPT (Keep, Problem, Try) 회고를 효과적으로 진행하기 위한 프롬프트와 가이드를 제공합니다.

---

## KPT 회고 기본 프롬프트

### 전체 회고 프롬프트

```
프로젝트 [프로젝트명]에 대한 KPT 회고를 진행하겠습니다.

1. Keep (유지할 것)
   - 프로젝트에서 잘 작동하고 있는 부분은 무엇인가요?
   - 계속 유지해야 할 좋은 관행이나 패턴은 무엇인가요?
   - 성공적인 기능이나 접근 방법은 무엇인가요?

2. Problem (문제점)
   - 현재 겪고 있는 문제점이나 어려움은 무엇인가요?
   - 개선이 필요한 부분은 무엇인가요?
   - 기술적 부채나 제약사항은 무엇인가요?

3. Try (시도할 것)
   - Problem을 해결하기 위한 구체적인 시도 방안은 무엇인가요?
   - 다음 단계에서 시도해볼 개선 사항은 무엇인가요?
   - 실험해볼 새로운 접근 방법은 무엇인가요?
```

## 세부 프롬프트

### Keep (유지) 작성 프롬프트

```
다음 질문에 답하며 Keep 항목을 작성하세요:

1. 코드 품질
   - 잘 작동하는 코드 패턴이나 구조는 무엇인가요?
   - 재사용 가능한 컴포넌트나 모듈은 무엇인가요?
   - 코드 리뷰에서 칭찬받은 부분은 무엇인가요?

2. 프로세스
   - 효과적인 개발 프로세스나 워크플로우는 무엇인가요?
   - 잘 작동하는 협업 방식은 무엇인가요?
   - 효율적인 커뮤니케이션 방법은 무엇인가요?

3. 기능
   - 사용자에게 좋은 평가를 받은 기능은 무엇인가요?
   - 안정적으로 작동하는 기능은 무엇인가요?
   - 성능이 우수한 부분은 무엇인가요?

4. 도구/기술
   - 생산성을 높여준 도구나 라이브러리는 무엇인가요?
   - 효과적인 기술 스택은 무엇인가요?
   - 잘 작동하는 개발 환경은 무엇인가요?
```

### Problem (문제) 작성 프롬프트

```
다음 질문에 답하며 Problem 항목을 작성하세요:

1. 기술적 문제
   - 코드에서 개선이 필요한 부분은 무엇인가요?
   - 성능 병목이나 메모리 이슈는 무엇인가요?
   - 버그나 에러가 자주 발생하는 부분은 무엇인가요?

2. 구조적 문제
   - 코드 구조에서 문제가 되는 부분은 무엇인가요?
   - 유지보수가 어려운 부분은 무엇인가요?
   - 확장성이 부족한 부분은 무엇인가요?

3. 프로세스 문제
   - 개발 프로세스에서 비효율적인 부분은 무엇인가요?
   - 협업에서 문제가 되는 부분은 무엇인가요?
   - 커뮤니케이션에서 개선이 필요한 부분은 무엇인가요?

4. 문서/테스트 문제
   - 문서화가 부족한 부분은 무엇인가요?
   - 테스트 커버리지가 낮은 부분은 무엇인가요?
   - 테스트가 어려운 부분은 무엇인가요?

5. 사용자 경험 문제
   - 사용자 피드백에서 지적된 문제는 무엇인가요?
   - UI/UX에서 개선이 필요한 부분은 무엇인가요?
   - 사용성이 떨어지는 기능은 무엇인가요?
```

### Try (시도) 작성 프롬프트

```
다음 질문에 답하며 Try 항목을 작성하세요:

1. 즉시 실행 가능한 개선 (Quick Wins)
   - 빠르게 해결할 수 있는 문제는 무엇인가요?
   - 낮은 비용으로 큰 효과를 볼 수 있는 개선은 무엇인가요?
   - 1-2일 내에 완료 가능한 작업은 무엇인가요?

2. 단기 개선 (1-2주)
   - 다음 스프린트에서 시도해볼 개선은 무엇인가요?
   - 리팩토링이 필요한 부분은 무엇인가요?
   - 테스트를 추가해야 할 부분은 무엇인가요?

3. 중장기 개선 (1-2개월)
   - 아키텍처 개선이 필요한 부분은 무엇인가요?
   - 새로운 기술이나 도구를 도입해야 할 부분은 무엇인가요?
   - 대규모 리팩토링이 필요한 부분은 무엇인가요?

4. 실험적 시도
   - 새로운 접근 방법을 시도해볼 부분은 무엇인가요?
   - 프로토타입을 만들어볼 기능은 무엇인가요?
   - A/B 테스트를 해볼 부분은 무엇인가요?

각 Try 항목에 대해:
- 구체적인 액션 아이템은 무엇인가요?
- 예상 소요 시간은 얼마인가요?
- 우선순위는 어떻게 되나요?
- 성공 기준은 무엇인가요?
```

### ChatGPT/Claude 등 AI 도구 사용 시

```
당신은 소프트웨어 개발 프로젝트의 KPT 회고를 도와주는 전문가입니다.

프로젝트 정보:
- 프로젝트명: [프로젝트명]
- 기술 스택: [기술 스택]
- 주요 기능: [주요 기능]
- 최근 완료한 작업: [최근 작업]
- 현재 이슈: [현재 이슈]

다음 항목에 대해 분석하고 KPT 회고를 작성해주세요:

1. Keep (유지할 것)
   - 잘 작동하는 코드 패턴
   - 효과적인 프로세스
   - 성공적인 기능

2. Problem (문제점)
   - 기술적 부채
   - 개선이 필요한 부분
   - 제약사항

3. Try (시도할 것)
   - 구체적인 액션 아이템
   - 우선순위와 예상 소요 시간
   - 성공 기준

각 항목은 구체적이고 실행 가능하게 작성해주세요.
```

### 코드베이스 분석 기반 프롬프트

```
다음 코드베이스를 분석하여 KPT 회고를 작성해주세요:

[코드베이스 정보]

Keep 항목 작성 시:
- 잘 구조화된 코드
- 재사용 가능한 패턴
- 명확한 네이밍

Problem 항목 작성 시:
- 코드 스멜 (긴 메서드, 큰 클래스, 중복 코드 등)
- SOLID 원칙 위반
- 테스트 커버리지 부족
- 성능 이슈

Try 항목 작성 시:
- 리팩토링 제안
- 테스트 추가 계획
- 아키텍처 개선 방안
```

## 회고 진행 체크리스트

### 회고 전 준비
- [ ] 프로젝트 상태 파악 (최근 커밋, 이슈, PR 확인)
- [ ] 주요 지표 수집 (테스트 커버리지, 코드 품질 메트릭 등)
- [ ] 팀원 피드백 수집 (있는 경우)
- [ ] 사용자 피드백 확인 (있는 경우)

### 회고 중
- [ ] Keep 항목 5개 이상 작성
- [ ] Problem 항목 5개 이상 작성
- [ ] Try 항목 5개 이상 작성
- [ ] 각 항목에 구체적인 예시 포함
- [ ] 우선순위 설정

### 회고 후
- [ ] Try 항목을 액션 아이템으로 변환
- [ ] 담당자와 마일스톤 할당
- [ ] 다음 회고 일정 설정
- [ ] 회고 결과 공유

- [ ] 항목 1: 구체적인 설명

## Problem (문제점)

### 1. [카테고리]
- [ ] 항목 1: 구체적인 설명 및 영향도
- [ ] 항목 2: 구체적인 설명 및 영향도

- [ ] 항목 1: 구체적인 설명 및 영향도

## 효과적인 KPT 회고를 위한 팁

### 1. 구체성
- ❌ 나쁜 예: "코드 품질 개선 필요"
- ✅ 좋은 예: "DefectAnalysisGUI 클래스가 1300+ 라인으로 너무 큼. 단일 책임 원칙 위반"

### 2. 측정 가능성
- ❌ 나쁜 예: "성능 개선"
- ✅ 좋은 예: "이미지 분석 시간을 현재 평균 5초에서 3초로 단축"

### 3. 실행 가능성
- ❌ 나쁜 예: "코드 품질을 높인다"
- ✅ 좋은 예: "DefectAnalysisGUI를 ImageDisplay, StatisticsDisplay, ReportDisplay로 분리 (예상 소요: 1주)"

### 4. 우선순위 명확화
- 각 Try 항목에 우선순위(높음/중간/낮음) 설정
- 비즈니스 가치와 기술적 부채의 균형 고려

### 5. 정기적인 업데이트
- 스프린트 종료 시마다 KPT 회고 진행
- Try 항목의 진행 상황 추적
- 완료된 항목은 다음 회고에서 Keep으로 이동
